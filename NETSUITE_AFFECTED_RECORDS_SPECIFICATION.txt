3.1. VENDOR PAYMENT
--------------------------------------------------------------------------------
- NetSuite Internal ID: vendorpayment (Transaction Type: VendPymt)
- Record Category: Standard Transaction
- Primary Functional Role: Outgoing disbursement for vendor bills.

A. Custom Fields Added to Record:

      - Values: '1' = Real-Time CIPS, '2' = Non-Real-Time IPS.
   2. custbody_rdnchl_bank (List/Record -> customrecord_rd_nchl_bank_detail)
      - Stores the selected beneficiary bank account for this payment.
   3. custbody_rdnchl_paid_online (Checkbox)
      - Locked flag. Automatically set to TRUE when NCHL returns success code '000'.
   4. custbody_ird_voucher_no (Free-Form Text)
      - Copied from Vendor Bill if paying government tax.
   5. custbody_npi_request_body (Long Text)
      - Copied from Vendor Bill if paying Department of Customs duty.

B. Scripts Operating on this Record:
   - payment_button_ues.js (User Event):
     * beforeLoad (view mode): If approvalstatus == '2' (Approved) and
       custbody_rdnchl_paid_online == false, injects "Pay Online" button.
     * beforeLoad (create/edit mode): Injects dynamic dropdown custpage_entity_bank
       and copies bill tax/voucher properties.
   - payment_client.js (Client Script):
     * fieldChanged: When custbody_nchl_payment_type changes, dynamically filters
       custpage_entity_bank between CIPS and IPS accounts.
   - payment_confirm_page_sl.js (Suitelet):
     * Loads the payment record, displays confirmation UI, submits payment to NCHL,
       and updates custbody_rdnchl_paid_online = true.
   - mpmod.js (Saved Search Module):
     * Filters approved, unpaid vendor payments for mass batch processing.
   - process_multiple_payment_sl.js (Suitelet):
     * Renders payments in a sublist with checkboxes for bulk processing.
   - schedule_process_multiple_payment.js (Scheduled Script):
     * Loads queued payment records in background, dispatches batches, and sets
       custbody_rdnchl_paid_online = true.

4. CROSS-RECORD ENTITY RELATIONSHIP & DATA FLOW ARCHITECTURE
================================================================================

```
+-------------------+           +-------------------------------------+
|      Vendor       | 1 ----- N |  customrecord_rd_nchl_bank_detail   |
|     (vendor)      |           |          (Payee Bank Record)        |
+-------------------+           +-------------------------------------+
          |                                        |
          | 1                                      | 1
          |                                        |
          v N                                      v N
+-------------------+           +-------------------------------------+
|    Vendor Bill    | 1 ----- 1 |           Vendor Payment            |
|   (vendorbill)    |           |          (vendorpayment)            |
+-------------------+           +-------------------------------------+
                                                   |
                                                   | 1
                                                   v 1
+-------------------+           +-------------------------------------+
|   Account (COA)   | 1 ----- N |    customrecord_nchl_transaction    |
|   (account GL)    |           |          (NCHL Gateway Log)         |
+-------------------+           +-------------------------------------+
          |                                        ^
          | 1 (From / To)                          | 1
          v                                        |
+-------------------+                              |
|   Bank Transfer   | 1 ---------------------------+
|    (transfer)     |
+-------------------+
          |
          | 1 (Debit / Credit)
          v
+-------------------+
|   Journal Entry   | 1 ---------------------------+
|  (journalentry)   |
+-------------------+
```

RELATIONSHIP SUMMARY:
1. One Vendor can have Multiple NCHL Bank Detail records (1:N).
2. One Account (GL Bank) links to its respective CIPS and IPS Bank Detail records (1:1).
3. Vendor Bill assessment payloads copy down to child Vendor Payments upon bill payment.
4. Vendor Payment, Journal Entry, or Bank Transfer generates One primary
   NCHL Transaction Log record per payment run (1:1).
5. Successful clearance in NCHL updates the originating transaction's
   custbody_rdnchl_paid_online flag to TRUE.
