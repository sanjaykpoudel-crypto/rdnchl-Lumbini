1. OVERVIEW OF OUTGOING PAYMENT CAPABILITIES
================================================================================
The outgoing payment subsystem allows NetSuite to electronically disburse funds
directly from corporate bank accounts via NCHL / NPI / connectIPS gateways:

A. Single Vendor Payments & Prepayments:
   - Real-time CIPS (connectIPS instant settlement up to transaction limit).
   - Non-real-time IPS (Batch clearing through NCHL clearing cycle).
B. Government & Biller Payments:
   - Inland Revenue Department (IRD): Tax payments with voucher validation.
   - Department of Customs (DOC): Customs duty payments with automated NECAS
     assessment retrieval.
C. Bulk & Multi-Line Disbursements:
   - Journal Entry line disbursements (multiple creditor beneficiaries from a
     single funding debit account).
   - Mass batch execution of multiple approved vendor payments via Scheduled Script.
D. Outbound Bank Transfers:
   - Disbursing funds from an originating bank account to another internal account.

2. OUTGOING PAYMENT SCRIPTS & FUNCTIONAL ROLES
================================================================================

1. Core Communication & Digital Signature:
   - rdmodule.js:
     Server-side module. Generates OAuth bearer token (/oauth/token), signs batch
     payload with SHA-256 digital certificate, and dispatches POST requests to
     /api/postcipsbatch, /api/postnchlipsbatch, and biller endpoints.
   - npiconfig.js:
     Stores gateway host, API user credentials, and certificate ID.
   - configfile.js:
     Controls postonapprove behavior and certificate linkage.

2. Single Payment UI & Execution:
   - payment_button_ues.js (User Event on Vendor Payment / Bill):
     Adds "Pay Online" button when payment status is Approved (approvalstatus == '2')
     and unpaid (!custbody_rdnchl_paid_online). In create/edit mode, filters and
     populates creditor bank accounts.
   - payment_client.js (Client Script on Vendor Payment):
     Dynamically updates available bank accounts when toggling CIPS vs IPS.
   - payment_confirm_page_sl.js (Suitelet: customscript_payment_detail_confirm_sl):
     Renders debtor and creditor confirmation screen, computes instruction payloads,
     executes NCHL batch API call, updates payment status, and saves transaction log.
   - suitelet_client.js (Client Script):
     Client handler on payment_confirm_page_sl.js to dynamically switch creditor bank.

3. Bulk & Multi-Line Payments (Journal Entry & Bulk):
   - bulk_pmt_button_ues.js (User Event):
     In view mode, adds "Pay Online" button linking to bulk payment Suitelet.
   - bulkpayment_confirm_page_sl.js (Suitelet: customscript_bulk_payment_page):
     Extracts debit account (funding bank) and all credit lines (beneficiaries with
     custcol_col_entity_bank), formats a multi-instruction batch, signs and posts to NCHL.
   - journal_nchl_btn_ues.js (User Event on Journal Entry):
     Adds "Online Payment" button when Journal Entry is approved.
   - journal_process_payment_sl.js (Suitelet: customscript_nchl_process_jrnl_payment):
     Suitelet entry point for Journal Entry disbursements.

4. Mass Batch Queue Processing:
   - process_multiple_payment_sl.js (Suitelet: customscript_process_multi_pmt):
     Presents a sublist of approved, unpaid vendor payments and prepayments with
     checkboxes for mass selection.
   - mpmod.js (Custom Module):
     Provides the saved search query to populate unpaid approved transactions.
   - schedule_process_multiple_payment.js (Scheduled Script: customscript_process_payment_schedule):
     Background engine that iterates over queued transactions, posts CIPS/IPS batches,
     and marks each transaction as paid online.

5. Government Tax & Customs (IRD & DOC):
   - vendor_type_from_npi_ues.js (User Event on Vendor):
     Classifies vendors as Government / IRD / DOC.
   - ventypeclient.js (Client Script on Vendor):
     Cascading UI selection for vendor categories.
   - get_ird_detail_ues.js (User Event on Vendor Bill):
     Renders DOC Customs Office dropdown and "DOC Detail" button for customs vendors.
   - get_ird_detail_cs.js (Client Script on Vendor Bill):
     Launches popup Suitelet to query DOC customs assessment details.
   - get_doc_payment_detail_sl.js (Suitelet: customscript_get_npi_doc_detail):
     Queries NPI NECAS API (/api/tp/necas/detail), returns tax amount, and updates Bill.

   - custrecord_ips_bank                  (List/Record -> customrecord_rd_nchl_bank_detail for IPS)

4. OUTGOING PAYMENT FLOWS
================================================================================

FLOW A: STANDARD VENDOR PAYMENT (SINGLE)
1. Vendor Bill is entered with approved vendor and bank account.
2. Bill is paid via "Pay Bills" creating a Vendor Payment record.
3. On Vendor Payment:
   - User selects 'custbody_nchl_payment_type' (1 = CIPS Real-Time or 2 = IPS).
   - User selects 'custbody_rdnchl_bank' (Vendor's bank account).
4. When Vendor Payment is Approved (approvalstatus = '2'):
   - payment_button_ues.js displays "Pay Online" button.
5. Clicking "Pay Online" opens Suitelet: payment_confirm_page_sl.js.
6. The user verifies Debtor Bank (from COA) and Creditor Bank (from Vendor Bank Detail).
7. Clicking "Make Payment" triggers:
   - rdmodule.savenchltran() -> creates customrecord_nchl_transaction.
   - rdmodule.postcipsbatch() or postipsbatch() -> generates digital token and posts to NCHL.
   - If response code is '000', sets custbody_rdnchl_paid_online = TRUE on Vendor Payment.
   - Redirects user to customrecord_nchl_transaction record showing status.

FLOW B: BULK JOURNAL DISBURSEMENTS
1. User creates a Journal Entry where:
   - Debit line = Bank Account (Funding Debtor Account).
   - Multiple Credit lines = Beneficiary Payees, each having custcol_col_entity_bank selected.
2. Journal Entry is Approved.
3. bulk_pmt_button_ues.js displays "Pay Online" button.
4. Clicking opens bulkpayment_confirm_page_sl.js.
5. The Suitelet aggregates all credit lines into a single NCHL batch with multiple instructions.
6. User clicks submit -> batch posted to NCHL -> custbody_rdnchl_paid_online set to TRUE.

FLOW C: MASS VENDOR PAYMENT BATCH QUEUE
1. User navigates to customscript_process_multi_pmt Suitelet.
2. Suitelet displays all approved, unpaid Vendor Payments.
3. User selects records via checkboxes and submits.
4. Suitelet triggers Scheduled Script customscript_process_payment_schedule.
5. Scheduled Script runs in background, processes payments, posts to NCHL, and marks records.

FLOW D: GOVERNMENT TAX & CUSTOMS DUTY PAYMENTS (IRD & DOC)
1. For IRD: Vendor Bill created with vendor type IRD, entering custbody_ird_voucher_no.
2. For DOC (Customs): Vendor Bill created with vendor department 'DOC-FORM'.
   - User clicks "DOC Detail" button -> opens get_doc_payment_detail_sl.js popup.
   - User enters Registration No, Year, Serial -> NECAS API returns assessment amount.
   - Form auto-populates tax amount and saves custbody_npi_request_body on the Bill.
3. When the Bill is paid, payment_confirm_page_sl.js uses /api/billpayment/lodgebillpay.do
   and confirmbillpay.do to complete government clearance.

5. STEP-BY-STEP IMPLEMENTATION GUIDE TO MAKE ALL SCRIPTS WORK AT ONCE

1. Obtain the client .pfx / .p12 certificate file and private key password from NCHL.

3. Create New Certificate:
   - Name: NPI Live Certificate
   - Script ID: custcertificatenpilive (must match npiconfig.js CERTIFICATE_ID)
   - Upload your certificate file and enter the password.

STEP 2: CREATE FILE CABINET FOLDER & CONFIGURATION
1. Go to Documents > Files > File Cabinet.
2. Create a folder named: npiconfig (or note down its internal ID).
3. Ensure npiconfig.js and configfile.js exist in your script folder.

STEP 3: CREATE CUSTOM RECORDS & FIELDS

4. Create Custom Transaction Body Fields listed in Section 3.C.
5. Create Custom Transaction Column Field (custcol_col_entity_bank) listed in Section 3.D.
6. Create Custom Account Fields listed in Section 3.E.

STEP 4: SETUP CHART OF ACCOUNTS (BANK ACCOUNTS)
1. For each bank account in NetSuite used for outgoing payments:
   - Create a corresponding customrecord_rd_nchl_bank_detail record (with Bank Type CIPS and/or IPS).
   - In the Account record, assign custrecord_rdnchl_coa_bank_detail and custrecord_ips_bank.

STEP 5: SETUP VENDORS & VENDOR BANKS
1. For each payee vendor:
   - Create the vendor's bank account under customrecord_rd_nchl_bank_detail, linking it to the vendor.
